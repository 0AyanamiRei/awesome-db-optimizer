# L08 · 如何从已有 FD 推出新 FD

原文：§6.1 后半部分，印刷页 208，[PDF 第 229 页](../../Query%20opt.pdf#page=229)。六条推理规则、$F^+$、超键与键的定义来自原文；规则的直观解释、推导过程、属性闭包算法和例题是教学补充。本节继续假设属性不含 NULL。

> **本节回答三个问题**
>
> 1. 已知几条 FD，怎样不看数据就推出新的 FD？
> 2. 怎样判断一组属性能不能决定整条记录？
> 3. 超键和键有什么区别？

## 1. 为什么需要推理规则

L07 的排序例子里，我们用“串起来”的直觉推出了 `c.id` 决定 `n.name`。优化器不能靠直觉，也不能去扫描数据（数据随时会变）。它需要一套**只操作属性集合**的规则：输入若干条已知 FD，机械地输出新的 FD。原书使用 Armstrong 公理。

下面 $A_1, A_2, A_3, A_4$ 都是属性集合；$\subseteq$ 表示“是子集（可以相等）”，$\cup$ 表示把两组属性合起来。示例中 `AB` 是 $\{A, B\}$ 的简写。

## 2. 三条公理（原文）

| 编号 | 名称 | 规则 | 一句话 | 例子 |
| --- | --- | --- | --- | --- |
| 1 | 自反律 reflexivity | $A_2 \subseteq A_1 \Rightarrow A_1 \to A_2$ | 整体决定自己的一部分 | `AB → A` |
| 2 | 增广律 augmentation | $A_1 \to A_2 \Rightarrow (A_1 \cup A_3) \to (A_2 \cup A_3)$ | 两边加上同一组列 | `A → B` 得 `AC → BC` |
| 3 | 传递律 transitivity | $A_1 \to A_2 \land A_2 \to A_3 \Rightarrow A_1 \to A_3$ | 两步连成一步 | `A → B`、`B → C` 得 `A → C` |

为什么它们都成立？每条都可以用 L07 的定义“任取两条记录”来验证：

- **自反律**：两条记录在 $A_1$ 的每一列上相同，那么在其中一部分列 $A_2$ 上当然也相同。它不需要任何数据约束，所以叫**平凡 FD**。
- **增广律**：两条记录在 $A_1 \cup A_3$ 上相同，意味着在 $A_1$ 上相同（于是由已知 FD 得 $A_2$ 相同），并且在 $A_3$ 上相同。合起来，$A_2 \cup A_3$ 相同。
- **传递律**：$A_1$ 相同 ⇒ $A_2$ 相同 ⇒ $A_3$ 相同。

原书说这三条公理 **sound and complete**：

- **可靠**（sound）：用它们推出的 FD 一定成立，不会推错；
- **完备**（complete）：凡是由已知 FD 必然成立的 FD，都能用它们推出来，不会漏掉。

所以“某条 FD 能否由 F 推出”和“某条 FD 是否由 F 必然成立”是同一个问题。

### 用公理重做排序例子（教学补充）

在连接结果中有三条已知 FD。第二条来自连接条件：相等的两列互相决定；原书 §6.3 本应讨论这类算子规则，但未展开。

```text
f1: c.id  → c.nid    （customers 的键）
f2: c.nid → n.id     （连接条件 c.nid = n.id）
f3: n.id  → n.name   （nations 的键）

f1, f2 传递   ⇒  c.id → n.id
再与 f3 传递  ⇒  c.id → n.name
```

这就是 L07 “串起来”的形式化版本。

## 3. 三条派生规则（原文）

原书补充了三条实用规则。它们都能由三条公理推出，不是新的假设。

| 编号 | 名称 | 规则 | 一句话 |
| --- | --- | --- | --- |
| 4 | 合并律 union | $A_1 \to A_2 \land A_1 \to A_3 \Rightarrow A_1 \to (A_2 \cup A_3)$ | 右边可以合并 |
| 5 | 分解律 decomposition | $A_1 \to (A_2 \cup A_3) \Rightarrow A_1 \to A_2 \land A_1 \to A_3$ | 右边可以拆开 |
| 6 | 伪传递律 pseudotransitivity | $A_1 \to A_2 \land (A_2 \cup A_4) \to A_3 \Rightarrow (A_1 \cup A_4) \to A_3$ | 传递时带上额外的列 |

推导过程（教学补充）：

**合并律**

```text
A1 → A2      两边加 A1（增广）     ⇒  A1 → A1∪A2
A1 → A3      两边加 A2（增广）     ⇒  A1∪A2 → A2∪A3
上面两条传递                        ⇒  A1 → A2∪A3
```

**分解律**

```text
A2∪A3 → A2   （自反）
A1 → A2∪A3 与它传递                 ⇒  A1 → A2
A3 同理                             ⇒  A1 → A3
```

注意：分解律只拆**右边**。左边不能拆：`AB → C` 推不出 `A → C`。

**伪传递律**

```text
A1 → A2      两边加 A4（增广）     ⇒  A1∪A4 → A2∪A4
与 (A2∪A4) → A3 传递                ⇒  A1∪A4 → A3
```

例子：已知 `sid → sname` 和 `{sname, cid} → grade`，可得 `{sid, cid} → grade`。

## 4. FD 集合的闭包 $F^+$（原文）

设 $F$ 是已知的 FD 集合。原书定义：

$$
F^+ = \text{用上述规则从 } F \text{ 能推出的全部 FD}
$$

$F^+$ 包含 $F$ 自己，也包含大量平凡 FD（例如每个 `AB → A`）。它的元素是一条条 FD，不是属性。

$F^+$ 通常非常大，直接枚举不现实。实践中回答“$X \to Y$ 是否在 $F^+$ 中”，一般改为计算**属性闭包**。

### 属性闭包 $X^+$（教学补充）

原书没有给出这个算法，它是数据库教材中的标准做法。$X^+$ 表示“从 $X$ 出发，由 $F$ 能决定的全部属性”：

```text
X⁺ := X
重复：
    对 F 中每条 Y → Z：
        如果 Y ⊆ X⁺，就把 Z 加入 X⁺
直到 X⁺ 不再变化
```

有了它，判断就很简单：

$$
X \to Y \in F^+ \iff Y \subseteq X^+
$$

注意“如果 $Y \subseteq X^+$”这一步：多列左边的 FD 要等**所有**左边的列都进入 $X^+$ 后才能使用。

## 5. 超键与键（原文）

设 $A \subseteq A(R)$。

- **超键**（super key）：若 $A \to A(R)$ 成立，即 $A$ 决定全部属性。
- **键**（key）：$A$ 是超键，并且去掉任何属性后都不再是超键：

$$
\forall A' \big(A' \subset A \Rightarrow \lnot (A' \to A(R))\big)
$$

$\subset$ 表示真子集（至少少一个属性）。$\lnot$ 否定的是“这条 FD 成立”这个断言。

原文核对：p.208 的公式开头印作 $\forall A$，但括号中检查的是 $A'$，这里改为 $\forall A'$，并保留“$A$ 已是超键”的前提。见[边界记录 B15](../boundaries.md#b15--键定义的量词与教材补充例子的纠正)。

三个术语的关系：

| 术语 | 要求 | 一张表可以有几个 |
| --- | --- | --- |
| 超键 | 能决定全部属性 | 很多（在超键上再加列仍是超键） |
| 键（候选键） | 超键，且没有可删的列 | 一个或多个 |
| 主键 primary key | 从候选键中挑选一个 | 一个；原书本段不讨论 |

“键”的最小是指**没有多余的列**，不是指“列数最少”。两个候选键可以列数不同。

### 例题：选课表（教学补充）

$R$(`sid`, `sname`, `cid`, `cname`, `grade`)，已知：

```text
F = { sid → sname,   cid → cname,   {sid, cid} → grade }
```

逐个计算属性闭包：

| $X$ | $X^+$ | 是超键吗 |
| --- | --- | --- |
| `{sid}` | `{sid, sname}` | 否 |
| `{cid}` | `{cid, cname}` | 否 |
| `{sid, cid}` | `{sid, cid, sname, cname, grade}` | 是 |
| `{sid, cid, sname}` | 全部 | 是 |

`{sid, cid}` 的闭包计算过程：

```text
起点            {sid, cid}
sid → sname     {sid, cid, sname}
cid → cname     {sid, cid, sname, cname}
{sid,cid} → grade   {sid, cid, sname, cname, grade}  = 全部属性
```

结论：`{sid, cid}` 是超键；它的真子集 `{sid}`、`{cid}`、`∅` 都不是超键，所以它是键。`{sid, cid, sname}` 是超键但不是键，因为 `sname` 可以删掉。

## 小结与自测

- 三条公理（自反、增广、传递）可靠且完备；三条派生规则是它们的组合。
- 实际判断 $X \to Y$ 时计算 $X^+$，看 $Y$ 是否在里面。
- 超键决定全部属性；键在此基础上没有多余的列。

**自测**：$R(A, B, C, D)$，$F = \{A \to B,\; B \to C,\; AC \to D\}$。`AC` 是键吗？

<details>
<summary>答案</summary>

不是。先算 $A^+$：从 `{A}` 出发，用 `A → B` 得 `{A, B}`，用 `B → C` 得 `{A, B, C}`；这时 `A` 和 `C` 都已在闭包中，可以使用 `AC → D`，得到 `{A, B, C, D}`。所以 `A` 单独就是超键，而空集不是超键，因此 `A` 是键。`AC` 是超键，但含有多余的 `C`，不是键。

容易出错的地方是：看到 `AC → D` 的左边有 `C`，就以为必须把 `C` 放进候选键。其实 `C` 可以由 `A` 推出。

</details>
