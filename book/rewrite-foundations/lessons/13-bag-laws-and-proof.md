# L13 · 一条成立的分配律和一条反例

原文：§7.1.2，印刷页 213–214，[PDF 第 234–235 页](../../Query%20opt.pdf#page=234)。本节第一次完整使用 Bag 的重数函数证明等价，并构造反例说明“集合中成立”的式子不能直接搬到 Bag。

## 证明一条成立的等价

要证明：

> `X ∪ᵦ (Y ∩ᵦ Z) = (X ∪ᵦ Y) ∩ᵦ (X ∪ᵦ Z)`。

Bag 相等要求所有元素的重数相等。任取元素 `x`，记：

> `a = χˣ(x)`，`b = χʸ(x)`，`c = χᶻ(x)`。

左侧的重数是：

> `χˡʰˢ(x) = a + min(b,c)`。

右侧的重数是：

> `χʳʰˢ(x) = min(a+b,a+c)`。

对非负整数，`a + min(b,c) = min(a+b,a+c)`。因此对任意 `x`，左右重数相等；所以两个 Bag 相等。

这里的“任取 `x`”承担了全称证明的作用。几个样例数据相等，只能说明那些样例通过，不能代替这个逐点论证。

## 反例：另一条分配律失败

考虑看起来很熟悉的式子：

> `X ∩ᵦ (Y ∪ᵦ Z) = (X ∩ᵦ Y) ∪ᵦ (X ∩ᵦ Z)`。

令同一个元素 `1` 的重数为：

> `χˣ(1)=5`，`χʸ(1)=3`，`χᶻ(1)=3`。

左侧：

> `X ∩ᵦ (Y ∪ᵦ Z)` 的重数 `= min(5,3+3)=5`。

右侧：

> `(X ∩ᵦ Y) ∪ᵦ (X ∩ᵦ Z)` 的重数 `= 3+3=6`。

5 不等于 6，所以等价式失败。这个反例只使用了一个元素，说明问题来自重数运算本身，而不是复杂 schema 或 join。

## 再看截断差

原书还给出了差与并交的反例。令 `χˣ(1)=5`、`χʸ(1)=3`、`χᶻ(1)=3`：

> `(X ∪ᵦ Y) ∖ᵦ Z` 的重数 `= (5+3) ∸ 3 = 5`；
>
> `(X ∖ᵦ Z) ∪ᵦ (Y ∖ᵦ Z)` 的重数 `= (5∸3)+(3∸3)=2`。

两边再次不同。截断减法的 `max(0,·)` 会破坏一些普通整数减法中的分配直觉。

## 证明和反驳的区别

本节有两种证据：

- 对所有重数都成立的恒等式，需要逐点展开并证明一般等式；
- 要推翻一个“对所有输入成立”的说法，只需要一个合法重数反例。

这套方法会贯穿第七章：projection、join、grouping 的正确性证明可能需要重数、组对应或结构归纳；遇到疑似错误的等价式时，先尝试把数据缩减为一个元素和几个重数。

## 一个读者检查

如果把本节所有重数都限制在 `0` 或 `1`，Bag 运算就退化为集合运算，失败的反例也消失。这个观察解释了为什么 set 直觉经常在没有重复的测试数据上“看起来正确”，却在 SQL 的重复结果上失败。
