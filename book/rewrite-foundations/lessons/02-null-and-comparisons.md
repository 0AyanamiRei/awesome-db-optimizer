# L02 · NULL 改变了哪些操作

原文：§5.2、§5.2.1、§5.2.2，印刷页 199–201，[PDF 第 220–222 页](../../Query%20opt.pdf#page=220)，重点是图 5.3。下面的订单、值域写法和分组例子是教学展开；NULL 的传播规则和比较语义依据原书。本节先解释比较如何产生 UNKNOWN，下一节再讨论逻辑连接词如何处理它。

上一节中，`amount > 100` 对一条订单求值，只可能得到 TRUE 或 FALSE。那是因为我们暂时假定金额没有 NULL。现在允许一条订单的金额尚未填写：此时，比较运算的输入发生了变化，原先的定义需要扩展。

原书先把 NULL 看作一个有别于普通值的特殊标记，用来表达未知、未定义、不适用等情况。它不是金额 0，也不是空字符串；仅凭 NULL 本身，也不能知道缺失的具体原因。

用 `D` 表示一个普通值域，也就是某种类型允许的普通值的集合。为了讨论可空输入，我们可以把扩展后的值域写成：

> D_NULL=D ∪ {NULL}

这里 `∪` 表示集合的并，`{NULL}` 是只含这个特殊标记的集合。这是便于理解原文的教学记号：输入现在既可能是 `D` 中的普通值，也可能是 NULL。接下来的问题是，原来作用于 `D` 的运算，遇到新输入该怎么办？

先看算术。§5.2.1 说明，函数或运算的某个参数为 NULL 时，结果通常也为 NULL。原书特意给出了这个例子：

> 0 × NULL → NULL

这里用箭头表示“求值得到”，避免把 SQL 的相等比较与结果说明混在一起。

我们熟悉“任何数乘以 0 都是 0”，但 NULL 并不是普通的数。在原书讨论的算术规则下，乘法遇到 NULL 会返回 NULL，因此不能直接把这个表达式替换成 0。这与上一节的提醒一致：输入范围扩大后，旧的恒等式需要重新检查。

原文用的是“通常”，不能把它读成“所有函数都无条件传播 NULL”。每种操作仍有自己的定义；例如接下来会看到，专门检查 NULL 的 `IS NULL` 会返回真或假。

比较运算也需要扩展。原书在 §5.2.2 区分了三个很像、但不能混用的记号。

第一个是 `=ᵛ`，也就是普通值相等。上标 `v` 是记号的一部分，不表示乘方。它只接受不含 NULL 的普通值，例如：

> (7 =ᵛ 7) → TRUE, ； (7 =ᵛ 8) → FALSE

它没有负责回答“NULL 与 7 是否相等”。如果把 NULL 交给它，就是超出了这里给定的输入范围，不能自行补成 FALSE。

第二个是普通写法的 `=`，原书用它表示 **SQL 的相等比较**。两个输入都不是 NULL 时，它使用普通值比较；只要至少一个输入是 NULL，结果就是 UNKNOWN。

原书把 UNKNOWN 写成 `⊥`，读作“未知”。因此这个比较现在有三种可能的结果：

> {TRUE,FALSE,UNKNOWN}

要区分它们所在的位置：**NULL 是比较的输入中出现的特殊标记；UNKNOWN 是比较求值后可能产生的真值。** 在这里，UNKNOWN 既不是 TRUE，也不是 FALSE。SQL 可以把这个未知的布尔结果显示成 NULL，但阅读推导时，仍要分清输入值与比较结果。

第三个是 `≐`，本教材称作**点等号**。它也允许输入 NULL，但采用另一套规则：两个输入都是 NULL，返回 TRUE；恰好一个输入是 NULL，返回 FALSE；两个都不是 NULL，回到普通值比较。因此它永远只返回 TRUE 或 FALSE。

把三种比较放在一起，就能直接看到差别：


| 左输入 `x` | 右输入 `y` | 普通值比较 `x =ᵛ y` | SQL 比较 `x = y` | 点等号 `x ≐ y` |
| ------- | ------- | -------------- | -------------- | ----------- |
| 7       | 7       | TRUE           | TRUE           | TRUE        |
| 7       | 8       | FALSE          | FALSE          | FALSE       |
| NULL    | 7       | 不在定义域内         | UNKNOWN        | FALSE       |
| 7       | NULL    | 不在定义域内         | UNKNOWN        | FALSE       |
| NULL    | NULL    | 不在定义域内         | UNKNOWN        | TRUE        |


尤其要看最后一行。同样是两个 NULL，SQL 的 `=` 返回 UNKNOWN，点等号却返回 TRUE。它们并没有互相矛盾，因为它们是两个定义不同的比较操作。

把 NULL 想成“一个未知的金额”，可以帮助理解 SQL 比较：我们不知道两个缺失金额原本是否相同，所以不会得出 TRUE。但这只是帮助记忆的直觉；NULL 还可能表示不适用等情况，最终应以操作的定义为准。

点等号则明确规定，两个 NULL 标记在这种比较下归为相同。这个规定没有断言“背后缺失的两个真实金额一定相等”。

在 SQL 中，点等号对应的写法是：

```sql
x IS NOT DISTINCT FROM y
```

如果只想判断某个值是不是 NULL，使用的是另一个专门的判断：

```sql
amount IS NULL
```

它在金额为 NULL 时返回 TRUE，否则返回 FALSE。不能把它写成 `amount = NULL`：根据上表，后者无论金额为普通值还是 NULL，都得到 UNKNOWN。

为什么需要点等号？原书指出，分组与去重采用这种比较语义。看一张只有以下四条记录的订单表：


| order_id | region |
| -------- | ------ |
| 1        | east   |
| 2        | NULL   |
| 3        | NULL   |
| 4        | east   |


执行：

```sql
SELECT region, COUNT(*) AS n
FROM orders
GROUP BY region;
```

`COUNT(*)` 在这个例子里表示组内的行数。结果有两组，顺序不作要求：


| region | n   |
| ------ | --- |
| east   | 2   |
| NULL   | 2   |


两个 NULL 分组键归入同一组。这与 `NULL = NULL` 得到 UNKNOWN 并不冲突：分组时判定键是否相同，使用的是点等号语义。如果只投影 `region` 并使用 `SELECT DISTINCT`，同样会得到一个 `east` 和一个 NULL。

因此，以后遇到“两个值相同”时，需要看它出现在哪里：是在计算一个 SQL 比较谓词，还是在判定分组键或重复值。符号看起来接近，不代表规则相同。

§5.2.2 最后还讨论了不等与大小比较。对于 `<`、`≤`、`>`、`≥`，规则与 SQL 相等比较类似：任一输入为 NULL，比较结果就是 UNKNOWN；两个输入都不是 NULL，才使用相应的普通值比较。例如：

> (NULL>100) → UNKNOWN

不等可以通过否定相等来定义，例如 `x ≠ y` 表示 `¬(x=y)`。点等号的否定则是 `¬(x ≐ y)`。两者否定的是不同的比较，不能混用。原书还把大小比较的否定对应写成 `≤` 与 `>` 配对、`≥` 与 `<` 配对；这些表达式遇到 NULL 时也必须保留未知的情况。

我们到这里还没有定义 `¬UNKNOWN` 的结果，因此先不凭二值逻辑去计算它。下一节会给出 NOT、AND、OR 的完整三值真值表，接着解释同一个 UNKNOWN 为什么在 WHERE 和 CHECK 中会产生不同的接受行为。

你也可以先用上面的比较表做一个小检查：当金额为 NULL 时，`amount = amount` 与 `amount IS NOT DISTINCT FROM amount` 分别得到什么？直接代入最后一行，前者为 UNKNOWN，后者为 TRUE。即使左右引用的是同一个字段，也不能把 SQL 相等无条件当成恒真式。
