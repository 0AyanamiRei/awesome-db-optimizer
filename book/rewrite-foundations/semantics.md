# 语义契约：阅读 Foundations 时保持哪些区别

主教材沿 Moerkotte Part II 的概念和符号。这里整理跨章节约定，不用一套简化的 unnesting 模型代替原书。具体原文依据见[覆盖表](coverage.md)，记号见[符号表](notation.md)。

## 1. 先说明比较的对象

| 对象 | 什么叫相同 | 原文位置 |
| --- | --- | --- |
| 二值或三值谓词 | 对所有允许赋值，求值的真值相同 | §5.1、§5.3 |
| 经过 FALSE 解释的谓词 | FALSE 与 UNKNOWN 都不通过；只比较接受行为，不等于原始三值相同 | §5.3、§5.5 |
| Tuple | 属性名、对应类型及值相同；集合/重复判定中的 NULL 使用点等号语义 | §7.1、§7.3.1 |
| Set | 同样的元素存在 | §7.1.1 |
| Bag | 每一种元素的重数相同 | §7.1.2 |
| Sequence | 长度相同，而且对应位置上的元素相同 | §7.1.4 |
| 关系/集合值表达式 | 所有合法实例与绑定下，按输出类型的相等语义得到相同结果 | §7.6 |
| 查询包含 | 对所有数据库实例，结果满足相应语义下的包含 | 第 10 章 |

本书允许 nested values，属性值不一定是整数或字符串，也可以是 bag 或 sequence。比较嵌套值时必须递归采用其类型的语义，不能一律退化为平坦记录比较。

## 2. NULL 从第 5 章开始建立

主线不再采用“很晚才补 NULL”的安排。二值逻辑用于建立起点，随后立即引入三值逻辑。普通 `=`、点等号、=⁻、=⁺ 是不同的操作；特别是 NULL=⁺7 得到 TRUE，而 NULL≐7 得到 FALSE。

Selection 与普通 SQL 过滤只接受 TRUE。分组、重复判定使用点等号；outerjoin 补出的 NULL 又会进入后续表达式，必须重新检查谓词是否可能接受它。函数在全 NULL 输入上返回 NULL，与谓词在补 NULL 行上“不为 TRUE”也属于不同性质，不能只用一个“严格”标签混过。

为了便于算例，某一课可以明确限定“本例不含 NULL”。这个局部限定不能自动推广为全章或全书契约。

## 3. 类型、schema 与绑定

遵循 §7.3.1：先给出类型、属性名和作用域，再求值。e(t) 表示由 t 提供自由属性的绑定；一般算子参数可包含嵌套表达式。重命名要避免捕获，也要区分 tuple 的属性值与表示数据的隐藏列。

A(e) 和 F(e) 回答不同问题：e 产生什么，以及 e 仍依赖什么。没有数据行的结果仍有类型/schema；`[]` 是零属性 tuple；`{[]}ᵦ` 是包含一行的 bag；它们均不同于空 bag。

普通 product/join 的独立参数与 dependent operator 的受绑定参数分开定义。D-join 的左侧为右侧提供绑定是本书代数的一项能力，不是唯一需要作用域的场景：map、selection 的嵌套参数同样需要绑定规则。

教材原则上使用本书 e(t) 记号。如果为了讲解显式写出数据库实例 𝓘 和环境 η，将标作教学展开，而非作者已定义的新算子。

## 4. 重复控制和顺序控制分别管理

本书 Π_X 保留重复，Πᴰ_X 去重。Bag 的 ∪ 使用重数相加，与集合并及 ∪max 区分。Bag comprehension 中按出现次数枚举，与对各个不同值求和再乘其重数是两种等价的记账方式；不能同时使用而二次计数。

§7.16 的带帽算子需要单独检查顺序。其 product 采用确定的外内层枚举顺序；交换参数即使产生相同 bag，也可能产生不同 sequence。去重投影明确允许不保序，但要求确定性与幂等性；它不应被偷偷改成教材自行选择的“稳定保留第一次出现”。

Sequence 是正式学习范围，不被视为 optional。原书在具体序列算子上的疑似笔误和未充分规定之处见[边界记录](boundaries.md)。

## 5. 数据表示不是数据语义

§7.5 的 multiplicity、TID、position-based 表示需要一个“如何还原用户结果”的解释。教学会用明确的 encode/decode 箭头辅助说明，这是教学记号，不是新造物理执行框架。

表示转换的正确性应检查还原后是否相同；带 TID 的集合可以表示有重复的 bag。Bag 忘记顺序不损失其语义，sequence 忘记位置则可能损失信息。SQL 用户列、计数列、TID 和位置列在每个算例中分别标注。

TID 生成是原书专门引入的表示操作，不能被当作普通纯 map 而任意交换。其“每次出现都有不同编号”的要求与为相同 tuple 值计算同一个确定函数值不同。

## 6. 聚合函数和分组算子不是同一层

§7.2 的 agg 接收集合值并给出结果；§7.3 的 Γ 先组织组，再调用组函数；GJ 则由左输入逐项指定右侧的匹配组。原文的 `f` 有时可以返回复杂值，并不限于 SQL 的五个标量聚合。

每个聚合例子分别说明：是否忽略 NULL、是否去重、空输入如何定义、局部状态是什么、如何合并以及是否可逆。对 avg 的 sum/count 分解，进入含 NULL 例子时使用 non-null count，不能用总行数替代。

原文 decomposability 的开头限制分块非空，后面的 empty group/default 不能不经检查直接套用。分组键集合为空、输入 bag 为空、输入含一条全 NULL tuple，是三种不同情形；count(*) 尤其需要区分。

单记录组也不能使任意聚合都变为恒等函数，例如 count({7})=1。Grouping 与 map 的转换应逐聚合检查，不能把疑似过强的文字当通用规则。

## 7. 线性、重排和算法范围

强线性要求空输入映到空输出，且对 bag 加法并保持分配。弱线性增加输入 support 不相交的限制。两者都不是“任意两个算子可以交换”的同义词；还要证明 singleton 上的行为一致，并维护类型、属性和参数可见性。

普通函数的教学推导默认确定且没有可观察副作用，数值例子使用不会溢出的精确数值。涉及原书更广泛的方法调用、NULL、顺序、TID 或异常行为时，单独说明适用前提，不把纯函数恒等式宣称为所有 DBMS 表达式的实现保证。

§7.15 的正确性与完备性相对于作者定义的 core search space 和相应输入条件。它既不是全体 SQL 等价计划的完备枚举，也不能忽略 p.307 对 cross products 和 degenerate predicates 的限制。

## 8. 第 10 章按查询片段分别讨论

先在不含额外不等式的集合语义 CQ 上解释包含映射，再逐步讨论不等式、否定、约束和其他语义。不能把集合的 homomorphism 判据自动用于 bag，或把稠密有序域的比较推理自动用于整数域。

当说 q₁⊆q₂ 时，含义是对每个数据库实例成立，不是当前样例数据上的包含。经典 CQ 条件下，原文定理 10.1.1 的映射方向是 q₂→q₁。Union-of-CQ 的分支关系需要另外给出量词和映射方向，不能只沿用一幅箭头。
