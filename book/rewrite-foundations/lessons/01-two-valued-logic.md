# L01 · 为什么二值逻辑的常识需要重新检查

原文：§5.1 Two-Valued Logic，印刷页 199–200，[PDF 第 220–221 页](../../Query%20opt.pdf#page=220)，重点是图 5.1、5.2。下面的订单例子和逐步推导是教学展开；逻辑运算及恒等式来自原书。本节先限定为二值逻辑，NULL 的具体规则从下一节开始。

假设有一张订单表，我们要保留满足下面条件的订单：

```sql
WHERE amount > 100
   OR (amount > 100 AND status = 'paid')
```

你可能一眼就能看出，后面那一部分有些多余：金额超过 100 的订单已经被前半部分接受了，再补上“金额超过 100 并且已付款”并不会增加订单。这个判断很自然。现在我们把它写到足够精确，弄清楚它依赖哪些条件。

暂时假设 `amount` 和 `status` 都没有 NULL，比较运算能正常完成。同一个条件在同一条记录上求值，结果不变。这让我们能够先在最熟悉的二值逻辑里工作。

用 `p` 代表 `amount > 100`，用 `q` 代表 `status = 'paid'`。原条件就写成：

> p ∨ (p ∧ q)

这里的 `∨` 表示 OR，`∧` 表示 AND；稍后用到的 `¬` 表示 NOT。

先分清**条件表达式和条件的求值结果**。`amount > 100` 是一个等待记录提供金额的表达式。给它一条金额为 150 的记录，结果是 TRUE；给它一条金额为 80 的记录，结果是 FALSE。它自己并不是固定的 TRUE 或 FALSE。

如果用 `t` 表示一条记录，就可以把这个过程写成 `p(t)`：把记录 `t` 交给条件 `p`，得到一个真值。讨论逻辑恒等式时，我们进一步暂时不看金额和付款状态，只研究 `p`、`q` 分别取真、假时，复合表达式如何求值。

二值逻辑允许的真值只有两个：

> B={TRUE,FALSE}

NOT 接收一个真值并将其反转；AND 和 OR 各接收两个真值。AND 在两边都为真时为真，OR 在至少一边为真时为真。这些规则完整地决定了复合表达式的结果。

现在可以精确地表达开头的判断：

> p ∨ (p ∧ q) ≡ p

符号 `≡` 读作“等价”。**它要求：在这里允许的每一种真值赋值下，左右两边都得到相同结果。** 它不是给变量赋值，也不是 SQL 中的 `=` 比较。

这句话比“拿几条订单试过，结果一样”更强。后者只检查了若干输入；前者对所有允许的输入作了承诺。在二值逻辑里，两个变量恰好只有四种真值组合，所以我们可以把所有情况列完：

| `p` | `q` | `p ∧ q` | `p ∨ (p ∧ q)` | 右边的 `p` |
| --- | --- | --- | --- | --- |
| TRUE | TRUE | TRUE | TRUE | TRUE |
| TRUE | FALSE | FALSE | TRUE | TRUE |
| FALSE | TRUE | FALSE | FALSE | FALSE |
| FALSE | FALSE | FALSE | FALSE | FALSE |

最后两列逐行相同，而且没有遗漏其他可能的组合，因此等价成立。这条恒等式叫作**吸收律**，原书把它列在图 5.2 中。

也可以不用表格，直接按 `p` 分类推导。如果 `p` 为 TRUE，左边的 OR 已经有一个 TRUE，因此整个左边为 TRUE。如果 `p` 为 FALSE，内部的 `p ∧ q` 必然为 FALSE，于是整个左边也为 FALSE。两种情况下，左边都跟 `p` 相同；而二值逻辑里没有第三种情况。

回到订单，每条记录都会让两个条件落入表格中的某一行。因此，在本节的假设下，对每一条订单，上面的复杂条件都与 `amount > 100` 得到相同真值。这就说明了为什么可以简化它。

注意，这个论证讨论的是**结果**。例如交换律 `p ∧ q ≡ q ∧ p` 说明两边的真值相同，却没有规定数据库先计算哪个条件，也没有承诺两种执行方式耗时相同。原书在这里建立的是逻辑运算的规律。

图 5.2 中的其他常用恒等式，也可以用同样的方法理解。例如：

| 名称 | 一种形式 | 它表达的意思 |
| --- | --- | --- |
| 幂等律 | `p ∧ p ≡ p` | 重复合取同一个条件，真值不变 |
| 分配律 | `p ∧ (q ∨ r) ≡ (p ∧ q) ∨ (p ∧ r)` | 可以展开括号，并保留真值 |
| 德摩根律 | `¬(p ∧ q) ≡ ¬ p ∨ ¬ q` | “并非两者都成立”等于“至少一个不成立” |

这里的 `r` 只是第三个条件。现在不必把整张公式表背下来；遇到一条公式，先把其中的变量看作真值输入，就知道它在声称什么，也知道怎样检查它。

还有一条特别熟悉的规律：

> p ∨ ¬ p ≡ TRUE

这叫**排中律**。它的二值证明只有两种情况：如果 `p` 为 TRUE，左边为 TRUE；如果 `p` 为 FALSE，`¬ p` 为 TRUE，左边仍为 TRUE。类似地，`p ∧ ¬ p ≡ FALSE`。

但请留意证明中的一句话：“只有两种情况”。它不是无关紧要的背景，而是穷尽所有输入的依据。如果我们改变了允许的真值集合，就必须检查新输入下的结果；旧表格已经不能独自证明新系统中的等价。

这正是 §5.1 与后面 NULL、三值逻辑的联系。考虑下面这个条件：

```sql
WHERE amount > 100 OR NOT (amount > 100)
```

在刚才的二值假设下，它对每条记录都为 TRUE。可是，如果 `amount` 可以为 NULL，比较结果和 NOT 的行为就需要重新定义。不能只凭刚才的两行证明就删去这个条件。我们会在接下来两节定义这些规则，再亲自计算它的结果。

这也不意味着加入第三个真值后，所有熟悉的规律都会失效。每条规律都需要依据新的运算定义判断，不能因为排中律出了问题，就一并否定交换律或吸收律。

原书图 5.2 还列出了带 `∃`（存在）和 `∀`（所有）的公式，部分公式附有变量依赖和输入非空的条件。它们涉及“到哪些记录中检查条件”，比本节的真值组合多了一层。量词的最小语义、空输入条件和图中相关练习放在[补充课 L06b](06b-quantifiers-and-chapter-review.md)；后续第 7 章建立完整属性依赖和绑定记号时，再把这些规律接到代数算子上。

如果愿意，可以用一张四行真值表验证上面的德摩根律。需要比较的是 `¬(p ∧ q)` 与 `¬ p ∨ ¬ q` 两列；练习不影响继续阅读。
