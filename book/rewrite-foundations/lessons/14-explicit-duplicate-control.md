# L14 · 为什么要显式控制重复

原文：§7.1.3 Explicit Duplicate Control，印刷页 214–215，[PDF 第 235–236 页](../../Query%20opt.pdf#page=235)。本节解释把集合嵌入 Bag、set-faithfulness、`Πᴰ` 去重、union all/union distinct，以及为什么教材优先使用 Bag 算子再显式去重。

## 把集合看成没有重复的 Bag

任何集合都可以嵌入成一个 Bag：对集合中的元素保留重数 1，对其他元素保留重数 0。把这个嵌入记为 `Ī(S)`。

反过来，只有当一个 Bag 的所有重数都不超过 1 时，才可以安全地把它还原成集合，记为 `Ī⁻¹(B)`。如果 `B` 中有某个元素出现两次，这个反向函数没有定义，因为它无法保留重复信息。

## set-faithful 是什么

一个作用于集合的函数 `f` 是 set-faithful，如果把集合先嵌入成 Bag，执行 Bag 版本，再还原，结果与直接执行集合版本相同：

> `Ī⁻¹(f(Ī(X))) = f(X)`。

二元函数 `g` 的定义同理：

> `Ī⁻¹(g(Ī(X),Ī(Y))) = g(X,Y)`。

Bag 交和 Bag 差是 set-faithful：如果输入本来没有重复，min 和截断减法不会凭空产生重复。Bag 并不是 set-faithful，因为它会把两边的重数相加。

例如：

> `Ī({a}) ∪ᵦ Ī({a}) = {a²}ᵦ`。

直接做集合并的结果应是 `{a}`，两者不同。

## 只使用 Bag 算子，再显式决定是否去重

真实查询中，一个输入可能有主键而没有重复，另一个中间结果却是 Bag。此时不能要求整个表达式都使用集合 union，因为集合算子无法直接接受带重复的输入。更稳定的做法是：

1. 所有输入统一按 Bag 处理；
2. 使用保留重复的 `∪ᵦ`；
3. 只有语义需要集合结果时，显式应用去重。

原书用 `Πᴰ` 表示 duplicate elimination。对 Bag `B`：

> `χᴾᴵᴰ(B)(z) = min(1, χᴮ(z))`。

因此：

> `R₁ ∪ᴰ R₂ := Πᴰ(R₁ ∪ᵦ R₂)`。

这里的 `∪ᴰ` 对应 SQL 的 `UNION`/union distinct；`∪ᵦ` 对应保留重复的 union all 风格。去重不是“免费改变表示”，它可能需要排序、哈希或其他执行资源，所以只有在语义需要时才添加。

## 为什么要跟踪 duplicate-free 属性

把所有结果都写成 Bag 并不意味着可以忘记它是否含重复。优化器需要维护类似下面的事实：

- 某个基表有主键，因此结果在某些属性上 duplicate-free；
- projection 删除了键，可能让不同 tuple 碰撞；
- join 可能把一行复制成多个匹配结果；
- `Πᴰ` 明确恢复了集合性质。

如果后续算子要求集合，而当前只能证明“这是一个可能含重复的 Bag”，就需要显式插入 `Πᴰ`，或者证明某个更强的无重复条件。

## 本节的主线

第七章不会强迫所有表达式在集合和 Bag 两套算子之间来回切换。更统一的做法是把集合视为特殊 Bag，并把 duplicate elimination 作为显式语义操作。这样重复是否存在、何时消除、消除需要什么成本，都能在表达式中看见。
