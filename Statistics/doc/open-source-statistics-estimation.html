0. 先画边界：四条路径不能靠同名术语串起来

阅读生产系统时，最常见的偏移不是某个公式抄错，而是把一个层次的实现当成另一个层次的证据。 下面四条路径可以交换数据，但入口、状态和正确性问题都不同。

1

Statistics collection

ANALYZE 或后台任务怎样选 table、tablet、block、row，怎样从样本外推 NDV/null count。

2

Statistics storage

持久化的是 numeric NDV、HLL state、MCV、histogram，还是只保存在内存中的 zonemap。

3

Optimizer estimate

逻辑 Aggregate 如何把 child rows 与 grouping-column statistics 变成 output row count。

4

Query sampling

用户写下 TABLESAMPLE / SAMPLE 后，执行器实际跳过何种存储单位。

本文刻意不做的等同

不把用户可调用的 approx_count_distinct、uniq() 当 optimizer statistics； 不把 “使用 HLL” 当成实现了 Every Row Counts； 不把 “选择 tablet/block” 当成已经实现 SIGMOD 2004 的 2PHASE 或 COLLAPSE。

2. Doris 主线：从 tablet sample 到 GROUP BY row count

固定版本，而不是“Doris 一直如此”

本节只陈述 Apache Doris official master commit 68f54696ee86543277917d54ca1179290380580e 在 2026-08-03 的行为。统计代码演进较快，类名相同也应重新核对具体 commit。

一句话总览

Doris 已经形成 “tablet sample → 单列统计外推 → 内部表/缓存 → GROUP BY heuristic” 的完整生产链， 但这条链没有维护任意多列 sample frequency vector，也没有用单列 sketch bounds 做 SCBC correction； 因而它不是 CIDR 2019 方法的一个命名变体。

3. Doris Statistics collection：样本单位是 tablet，估计器是 linear / DUJ1

3.1 自动采样目标是 222 rows，但不是先从全表均匀抽 222 行

自动任务在选择 SAMPLE 方法时把 StatisticsUtil.getHugeTableSampleRows() 写入 job； 默认常量与 global session variable 都是 4,194,304 = 2²²。 这个值是目标行数，实际物理选择由 tablet 完成。 StatisticsAutoCollector L245–279 StatisticConstants L97–105

因为实现先选 cluster，再把 cluster 中的 rows 交给 SQL（或在其后截断），它没有实现“从全表 rows 独立等概率抽取”的 row-uniform sampler。特别是 tablet 大小不等、partition 按名称顺序访问、普通列 达到累计目标后的 early stop，以及超大 tablet 跳过/加回，都会影响行的 inclusion path。

按名称依次访问 partition；普通列并不保证覆盖全部 partition。

getSampleTablets() 用 partition 数量得到平均目标，再用每 tablet 平均行数估算当前已访问 partition 要选几个 tablet。partition 按名称排序；普通非 partition column 一旦累计 selectedRows ≥ targetSampleRows，就跳出当前及外层循环，后续 partition 不参与。 partition column 则不走这个 early stop，以争取每个 partition 至少选择一个 tablet。

每个已访问 partition 从一个 seek 开始循环选 tablet。

显式 seed 复用 seek；否则使用 SecureRandom。加入的是 tablet id， 不是 tablet 内独立 coin flip 的 row id。

tablet 是 cluster，必要时再加 LIMIT。

selected rows 不足时可能退化为 full scan；单个超大 tablet 会先跳过、必要时再加回。 普通非 key、非 partition column 可加 LIMIT 控制最终扫描行数； 普通 key column 为避免排序前缀破坏 NDV，通常不加 limit。

这些选择规则来自 OlapAnalysisTask L162–251 与 L259–323。

3.2 OLAP sampled analyze 的 MIN/MAX 是一次独立、无采样 query

doSample() 第一件事是调用 collectMinMax()。其模板为 SELECT MIN(col), MAX(col) FROM table，没有 TABLET(...) hint，也没有 sample LIMIT； 返回值随后作为常量填进 sampled analyze SQL。 BASIC_STATS_TEMPLATE L64–67 doSample / collectMinMax L108–159

本页为简洁也称它 “full MIN/MAX”：准确含义是完整扫描该 analysis task 指定的 table/index scope， 并非忽略 rollup/index 选择而强制扫描 base index。

错误读法：sample 分支的 getMinFunction() 返回 NULL，所以 OLAP sample 没有 min/max

BaseAnalysisTask.getMinFunction()/getMaxFunction() 的确在 tableSample != null 时返回 NULL，目的是防止通用/其他 sampled 模板把不准确极值送给优化器。 但 OlapAnalysisTask 没有用这个 sample 极值结果：它先跑上面的 full MIN/MAX query，再把结果注入模板。 BaseAnalysisTask L419–445

3.3 DUJ1 在样本 frequency counts 上外推单列 NDV

DUJ1 模板先按列值（字符串先取前缀 hash）分组，得到每个 observed value 的 sample frequency。 令 n = SUM(t1.count) 为 sample rows，d = COUNT(t1.col_value) 为非 NULL sample NDV， f₁ 为样本中只出现一次且非 NULL 的 value 数，N 为 FE/BE 提供的目标 table/index row count（tableRowCount），源码生成：

Doris BaseAnalysisTask.getNdvFunction() D̂DUJ1 = n · d / (n − f₁ + f₁ · n / N)

BaseAnalysisTask L428–437 这与 PostgreSQL 标量 NDV estimator 的思想有亲缘关系，但 Doris 输入是 tablet cluster sample 后的频数； 源码没有先按 tablet 执行 SIGMOD 2004 COLLAPSE，也没有记录每个 tablet 的 inclusion probability。

DUJ1 sampled branch 的 N 不是同一任务额外执行的精确 COUNT(*)： getSampleParams() 先放入 FE/BE reported table/index row count。只有数据量不超过 sample target、 因而转成 full scan 时，row count 才改用 COUNT(1)，而该分支同时改用 linear template。

3.4 什么时候不用 DUJ1

当前实现会在 full scan、partition-column sample 过大、single unique key、以及被分析列正好是唯一 distribution column 等条件下选择 linear template；否则使用 DUJ1。linear 路径通常把 sample NDV(col) 乘 scale factor， single unique key 可直接使用 table row count。 选择 estimator L309–323 useLinearAnalyzeTemplate L532–549

静态风险推断 cluster sample 与 DUJ1 假设之间需要实验

tablet 内常出现分区、排序或导入批次相关性。未触发 LIMIT 时，选中 tablet 的整簇 rows 直接形成 frequency counts； 触发 LIMIT 时，样本变成选中 tablets 范围内受 scan order 影响的截断 rows。再加上普通列可能只覆盖按名称排序的 partition 前缀，这些结构都可能改变 f₁ 与 sample NDV 的分布。 源码足以证明“tablet cluster selection + optional LIMIT + DUJ1”这条组合， 但不足以证明它在现实数据上产生可观测偏差，更不能据此称为确认 bug。需要按 tablet size、key clustering、 partition skew 分层构造数据并对 ratio error 做实验。

4. Doris Statistics storage：全局 numeric NDV、partition HLL 与单独 histogram

“Doris 使用 HLL”必须继续追问：保存的是哪个层级的 HLL？当前内部 schema 对全局列统计与 partition 统计采用不同表示。

Doris 三类持久化统计对象及其表示和读取边界
存储对象关键字段表示优化时读取方式
column_statistics count、ndv、null_count、min、max、data_size、update_time、hot_value 全局 ndv 是 BIGINT 点估计；min/max 是字符串编码；hot values 是可空字符串。 反序列化为 ColumnStatistic，并随 filter/join 等算子继续传播。
partition_statistics partition identity、count、ndv、null_count、min/max、data_size ndv 是 HLL 类型，可在合并 partition statistics 时 union/cardinality。 用于 partition 层统计与合并，不等同于 GROUP BY 任意组合 sketch。
histogram_statistics sample_rate、buckets、update_time 单列 histogram 独立保存；不是 column_statistics 每次自动附带的字段。 可由 statistics repository/cache 载入；本次未找到固定 commit 的 Nereids estimator 实际消费 buckets 的证据，GROUP BY 公式也没有读取。

Schema 证据： column_statistics L40–76 partition_statistics L78–111 histogram_statistics L113–135 partition HLL build/merge L219–252。

HLL state 与 numeric NDV 不是同一信息量

numeric NDV 可以参与乘法或 clamp，但不能像 HLL register state 那样 union； 单列 HLL 即使可 union，也不能凭空恢复任意列组合 (A,B) 的 joint NDV。 因而 “partition stats 有 HLL” 不能推出 “optimizer 已具备 CIDR 的 single-column sketch + row-sample hybrid”。

5. Doris GROUP BY estimator：先排序，再固定衰减；unknown 立即回退

Nereids 的 StatsCalculator.estimateGroupByRowCount() 是通用 Aggregate row-count 路径， 也被 distribution / shuffle-property 相关代码复用。它读取 child statistics 中每个 grouping expression 的 ColumnStatistic；直接找不到时，再由 ExpressionEstimation 估表达式统计。 StatsCalculator L1401–1463

5.1 三个分支

没有 GROUP key

直接返回 1，对应普通全局 aggregate。

任一 key unknown

不再使用其他已知 NDV，立即取 childRows × 1/3，再执行 max/min clamp。

全部 key known

NDV 降序；第一列不衰减，后续列按位置用 0.75 的递增幂次折扣。

常量在源码中明确为 DEFAULT_AGGREGATE_RATIO = 1/3 与 AGGREGATE_COLUMN_CORRELATION_COEFFICIENT = 0.75。 StatsCalculator L173–181

5.2 把源码写成准确公式

令 child row count 为 N，排序后的 grouping NDV 为 d₀ ≥ d₁ ≥ … ≥ dₖ₋₁。known 分支等价于：

Doris known-statistics branch；i 从 1 开始 G₀ = d₀
G = d₀ · ∏ max(1, dᵢ · 0.75^(i+1)),   i = 1 … k−1
result = min(N, max(1, G))

实现会在乘积超过 N 时提前停止并设为 N。当 N=0 时最后一次 min(result,N) 会得到 0，因此“区间 [1,N]”只适用于正 child cardinality。

5.3 手算一次：为什么先排序会改变每列承担的衰减

假设 N=1,000,000，原 SQL 的三个 key NDV 分别为 [10, 1000, 100]。 源码先排序为 [1000, 100, 10]： 

first key:                         1000
second factor: max(1, 100 × 0.75²) = 56.25
third factor:  max(1,  10 × 0.75³) = 4.21875

estimated groups = 1000 × 56.25 × 4.21875
                 = 237,304.6875
final cap        = min(1,000,000, 237,304.6875)

排序使最大 NDV 获得不衰减的位置，更小 NDV 承担更强折扣；这是一条工程 correlation heuristic， 不是从 child sample 的联合频数推导出的相关性估计。max(1, …) 还保证新增 key 不会把 group 数乘小。

5.4 与其他系统公式放在一起

四个系统在已核验 GROUP BY 路径中的多列组合与 fallback
系统多 key 组合相关性处理missing stats证据范围

6. Doris Query-facing TABLESAMPLE：也是 tablet，但不是 ANALYZE

Nereids parser 把百分比或行数及可选 seed 保存为 TableSample，translator 把它交给 OlapScanNode。OLAP scan 先把 percent/rows 换算为目标行数，然后按 partition 计算目标， 从 seek 位置循环选择 tablet，累计 tablet row count 直到达到目标。选中的仍是整 tablet。 LogicalPlanBuilder L5515–5527 OlapScanNode L861–943

与 stats collection 相似

  • 都可接受 rows / percent / seed。
  • OLAP 路径都在 tablet 粒度做主要选择。
  • 目标行数都可能因整 tablet 粒度而 overshoot。

与 stats collection 不同

  • 入口是用户 SELECT，不是 analyze job。
  • 结果直接进入查询算子，不写内部统计表。
  • 没有自动执行 DUJ1、scale factor 或 full MIN/MAX 支路。

复用 TableSample 数据结构，不等于复用统计语义

代码中相同类型可以承担“描述 sample 大小和 seed”的机械职责； 真正决定统计正确性的是后续调用了 OlapAnalysisTask 还是普通 OlapScanNode。

7. PostgreSQL：两阶段 ANALYZE sample + richer synopsis + 通用 group estimator

7.1 Statistics collection

standard ANALYZE 先用 Knuth Algorithm S 从 relation blocks 中无放回选至多 targrows 个 block， 再扫描选中 blocks，在 rows 上运行 Vitter reservoir，最终保留 targrows 行。 源码注释明确：每一行具有相同被选择机会，但并非每一种可能的行集合都等概率。 普通 scalar statistics 的最低样本请求为 300 × attstattarget，table-level target 取各列与扩展统计需求的最大值。 analyze.c L1229–1360 sample target L1999–2013 sampling.c L23–55

这不是简单地“选中 block 后把全部 rows 当最终 sample”。因此它可作为 Doris tablet sample 改进方向的一个设计参照， 但 block 与 tablet 的尺度、大小分布和读取成本不同，不能直接复制参数或概率结论。

7.2 Storage synopsis

pg_statistic 保存 null fraction、average width 与 NDV；NDV 可是绝对值，也可用负数表示相对 relation rows 的比例。 scalar slot 还可保存 MCV+frequency、排除 MCV 后的近似等频 histogram、物理/逻辑顺序 correlation。 pg_statistic.h L39–71 L183–225

7.3 GROUP BY estimate

planner 的普通 grouping 分支调用 estimate_num_groups()。它先尝试选择覆盖多个 grouping vars 的 extended ndistinct statistics；剩余 vars 再用单列 NDV，按 relation 组合、限制到 relation rows 的一部分， 并根据过滤后的 rows 做 domain occupancy 调整。跨 relation 再相乘，最终 cap input rows。 planner.c L3929–4031 selfuncs.c L3733–3802 L3994–4139

7.4 Query sampling

TABLESAMPLE BERNOULLI 扫描所有 pages，对每个 tuple offset 做独立 hash/coin flip； SYSTEM 对 block 做 hash，选中 block 后返回其中全部 tuple。 bernoulli.c L117–228 system.c L119–255

8. DuckDB：增量 NDV sample 与显式 ANALYZE full scan 是两条路

8.1 Statistics collection / storage

table append 时，ColumnStatistics.UpdateDistinctStatistics() 调用 DistinctStatistics.UpdateSample()。 它按类型把每个 vector 要处理的 count 设为 min(original_count, STANDARD_VECTOR_SIZE × rate)，一般 rate 为 0.1、整数为 0.3，且至少取 1。 因而满 vector 约取 10%/30%，短或尾 vector 可能 100% 纳入。随后直接把该 count 交给 hash/update； 源码没有随机索引选择，因此更准确的描述是 vector-prefix subsampling，不是 uniform reservoir。 distinct_statistics.hpp L19–54 distinct_statistics.cpp L25–47

HLL 的 sample distinct u 与 sample count s、total count n 再进入源码标为 Good–Turing 的外推。显式 ANALYZE 则扫描全部所选列，每个 chunk 调用非采样 Update， 最终替换 column distinct stats。 GetCount L53–67 PhysicalVacuum L18–104

不要写成 “DuckDB ANALYZE 抽 10%”

10%/30% 只是满 vector 时增量 append 维护 NDV 的近似比例；短 vector 可能全取。 当前显式 ANALYZE 则是 full column scan。

当前 RowGroupCollection.GetSample() 直接返回 nullptr；因此源码中残留的 table BlockingSample 接口也不能列作正在服务 optimizer 的 reservoir synopsis。 row_group_collection.cpp L2532–2538

8.2 GROUP BY estimate join-order-only evidence

在 RelationStatisticsHelper.ExtractAggregationStats() 中，只处理可映射为 child column 的 grouping expressions， 选 key 数最多的 grouping set。令单列 NDV product 为 D，key 数为 k，child rows 为 N：

D′ = D · 0.95^(k−1)
groups = min(N, D′ · (1 − exp(−N / D′)))

无可用 key stats 时回退 N/2；ungrouped aggregate 为 1。 该类位于 join-order statistics helper，本次没有找到足够证据把它描述为所有 standalone aggregate plan 的统一 estimator。 relation_statistics_helper.cpp L486–563

8.3 Query sampling

DuckDB 接受 TABLESAMPLE 与 USING SAMPLE，方法包括 SYSTEM、BERNOULLI、RESERVOIR。 固定 rows 未指定 method 时默认 RESERVOIR，percentage 默认 SYSTEM。 transform_select.cpp L1859–1886

SYSTEM 可下推的 table-scan 主路径

当 LogicalSample 直接位于无 filter 的 LogicalGet 上、且 table function 支持 sampling pushdown， optimizer 会把 SYSTEM options 移进 LogicalGet。RowGroup.PrepareScan() 在读取列数据前按 storage vector 决定整 vector 跳过/保留；row-count SYSTEM 则在 vector 内生成 systematic selection。

sampling_pushdown.cpp L9–55 row_group.cpp L823–865

不能下推时的 operator fallback

PhysicalStreamingSample 的 SYSTEM percentage 对上游每个 DataChunk 掷一次骰子并全取/全弃； SYSTEM rows 则在 chunk 内按全局计数与随机 phase 做 systematic row selection，并由 LIMIT 封顶。 BERNOULLI 每 tuple 掷一次；RESERVOIR 由 blocking reservoir operator 维护。

physical_streaming_sample.cpp L50–106 plan_sample.cpp L33–89

9. ClickHouse：全列 sketch builder 与 sampling-key query pruning

9.1 Statistics collection / storage

当前 MergeTree setting 默认自动统计类型为 basic, uniq_v2； materialize_statistics_on_merge=true，而 query setting materialize_statistics_on_insert=false。也可用显式 MATERIALIZE STATISTICS mutation 重建。 merge setting L641–643 auto types L1970–1974 insert setting L1968–1970

ColumnStatistics.build(column) 把完整 column 交给每个 statistics builder；TDigest 与 Count-Min 显式逐逻辑 row。 对普通 column，uniq_v2 把整个 raw column batch 交给 uniqCombined64(12)； 对 ColumnSparse 与 ColumnLowCardinality，它会利用物理表示，分别读取 values column 或 dictionary nested column。 因此本 commit 的源码证据是完整输入的 sketch aggregation（可利用编码），没有独立 row/block sampling layer。 Statistics.cpp L160–165 StatisticsUniqV2 L18–58

StatisticsUniqV2 复用 aggregate-function implementation，但其 state 由 statistics subsystem 按 part 构建和持久化；这与用户 SELECT 中临时执行 uniqCombined64() 是两个生命周期。

可用 synopsis 包括：basic 的 default/null 类计数、numeric min/max、string total bytes； uniq BJKST、uniq_v2 HLL 变体、TDigest 与 Count-Min Sketch。 TDigest 是 quantile sketch，Count-Min 是 frequency sketch；称它们为“直方图”会掩盖状态与误差模型差异。 官方类型说明 L1289–1343

官方文档与当前默认设置存在张力

同一文档仍写 statistics “updated when every insert comes”，但当前源码默认 insert materialization 关闭、merge 开启。 本页因此固定 commit 并以设置源码说明默认生命周期；文档句子不作为默认行为的唯一证据。

9.2 GROUP BY estimate join-order-only evidence

optimizeJoin.cpp 的 aggregation relation estimate 对每个 grouping key 读取 NDV，假设独立并相乘， 再 cap input rows。只要任一 key 缺 column stats，product 被清空，最终回退 input rows，并把来源标为 NoStatistics。这是 join reorder 递归估算路径；本次没有证据把它外推为全局统一 Aggregate estimator。 optimizeJoin.cpp L308–352 递归入口 L474–479

9.3 Query sampling

MergeTree SAMPLE k、SAMPLE n 与 SAMPLE k OFFSET m 要求建表时指定 sampling expression， 而且该 expression 必须包含在 primary key 中、结果类型必须是 unsigned integer。 执行时确定性地把 sampling key 映射到取值区间，以减少磁盘读取。最小读取单位仍是 granule；aggregate 不会自动按 sample factor 校正，需手工使用倍数或 _sample_factor。 MergeTree sampling key L92–99 SAMPLE docs L19–35 L55–67

发现与推断的分界

源码发现 Doris 选择整 tablet，普通列可能再 LIMIT；DUJ1 输入包含 sample singleton count；没有 per-tablet COLLAPSE state。

研究推断 tablet 内相关性可能使 DUJ1 的 f₁ 偏离 row-uniform sample；PostgreSQL 式二阶段 row reservoir 或重新推导的 cluster estimator 可能改善它。

尚未证明 当前误差是否显著、哪个 workload 最差、改用 reservoir/COLLAPSE 后收益是否覆盖 I/O 与 CPU 成本。

11. Doris 可借鉴路线：按工作负载范围逐级增加信息

下面不是“现成修复清单”，而是从最小改动到研究型方案的设计空间。每一步都增加维护、存储或读取成本， 应先以 current heuristic 为 baseline 测 ratio error、P99 与 analyze overhead。

先隔离 tablet clustering 的影响：选 tablet 后再做 row reservoir。

可参考 PostgreSQL “block selection → row reservoir” 的结构：把当前“未 LIMIT 时整簇纳入、LIMIT 时按 scan order 截断”改成在读出的 rows 中维护随机、固定容量 reservoir。它有机会部分降低大 tablet、块内重复或 scan order 对 sample composition 的支配。

Trade-off：仍需读取被选 tablet 才能看见 rows；reservoir 增加 hash/随机化与内存开销；tablet inclusion probability 和 LIMIT/scan order 仍需进入估计推导，不能声称自动得到 row-uniform sample。

对稳定热点组合，维护 extended multicolumn NDV。

PostgreSQL 展示了一条务实路线：不是为所有组合存 synopsis，而是由用户/工作负载选择常见列组；GROUP BY estimator 优先消费 joint NDV，再对未覆盖 columns 用单列 heuristic。

Trade-off：组合数量爆炸，需要 workload selection、刷新策略与 stale detection；joint NDV 解决指定组合， 不解决 ad-hoc 任意表达式。

只有目标确实是任意组合时，再研究 CIDR hybrid。

维护可更新单列 sketches，同时保留近似 row-uniform 的跨列 sample；查询时计算 frequency vector， 用 single-column bounds 修正 sample estimator。它直接针对 “预先不知道 GROUP BY 哪些列” 的问题。

Trade-off：需要 sample lifecycle、删除/更新语义、快速 frequency-vector engine、内存与延迟预算； 论文实验不能替代 Doris 数据模型和分布式执行上的重新评估。

若把 tablet 当 block 使用 COLLAPSE，先重建统计模型。

Doris tablet 通常大小不等；selection 按 partition 和目标 rows 决定，可能跳过超大 tablet、再加回，且 tablet 远大于论文中的物理 block。应先定义每行/每 tablet inclusion probability，再推导 estimator 并做 simulation。

Trade-off：这不是把公式中的 “block” 替换成 “tablet”。若等块、等概率与 cluster-scale 假设不成立， 原文 bias/variance 结论不能直接继承。

推荐实验矩阵

同时改变 tablet size CV、同值跨 tablet 扩散度、partition name/order 与 skew、key sorting、NDV 与 singleton ratio； 对比 current tablet+DUJ1、tablet+reservoir+DUJ1、linear、重新推导的 cluster estimator， 分别报告 mean/P95/P99 ratio error、扫描 bytes、collector CPU 和统计更新时间。

13. 一页结论

tablet cluster sample DUJ1 numeric NDV HLL state extended NDV GROUP BY heuristic query TABLESAMPLE
  1. Doris 的 sampled OLAP statistics 不是“sample 后所有字段都外推”：min/max 先单独 full scan； 其余字段走 tablet sample，并在 linear 与 DUJ1 间选择。
  2. Doris GROUP BY estimator 是明确可读的固定 heuristic：unknown 为 child/3；known NDV 降序并按位置用 0.75 衰减； 它没有观察 grouping columns 的 sample joint frequencies。
  3. PostgreSQL 提供了两种值得区分的工程参照：收集侧 block→row reservoir，估算侧 workload-selected multicolumn NDV； 两者都不是任意组合 SCBC。
  4. DuckDB 的 10%/30% 只是满 vector 时 append NDV 的前缀比例，短 vector 可全取，且不是 ANALYZE sample； ClickHouse 统计 builder 接收完整 column，并可利用 sparse/low-cardinality 编码，而不是另设随机 sampler。
  5. 若 Doris 要支持任意 ad-hoc GROUP BY 组合，CIDR hybrid 是研究方向；若要把 tablet 当 block 套 COLLAPSE， 必须先重新推导不等 tablet 与 partition-aware selection 下的概率模型。

最终心智模型

先问“这条信息从哪里采、以什么单位采”，再问“保存了什么状态”，最后才问“哪个 estimator 怎样消费它”。 只要这三问中有一问没有源码证据，就应把结论标成推断，而不是用相似算法名补齐缺口。
