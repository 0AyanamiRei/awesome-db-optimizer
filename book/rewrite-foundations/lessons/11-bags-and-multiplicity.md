# L11 · Bag 保存了集合遗漏的信息

原文：§7.1.2 Duplicate Data: Bags，印刷页 211–213，[PDF 第 232–234 页](../../Query%20opt.pdf#page=232)。本节定义 Bag、重数、成员关系、相等、子 Bag、基数和 singleton，并说明 NULL 元素如何计数。

SQL 查询默认保留重复行，因此只用集合无法表达完整结果。例如：

```text
{east, east, west}
```

如果把它当成集合，只能看到 `{east, west}`，丢失了 `east` 出现两次这一事实。Bag（multiset）保留这份信息。

## 重数函数

Bag `B` 仍然来自某个元素域 `D`，但每个元素可以出现任意非负整数次。用重数函数 `χᴮ` 表示：

> `χᴮ(x) ∈ ℕ₀`

它记录元素 `x` 在 `B` 中出现的次数。例如：

> `B = {a, b, b}ᵦ`
>
> `χᴮ(a) = 1`，`χᴮ(b) = 2`

也可以写成 `{a¹,b²}ᵦ`。如果所有元素的重数都不超过 1，这个 Bag 也可以被看作一个集合；但它的类型仍然可以是 Bag。

## 成员、相等和基数

Bag 成员关系只看重数是否大于零：

> `x ∈ B` 当且仅当 `χᴮ(x) > 0`。

两个 Bag 相等，当且仅当每个元素的重数都相等：

> `B = C` 当且仅当对所有 `x`，`χᴮ(x) = χᶜ(x)`。

子 Bag 关系可以逐点表达：

> `B ⊆ C` 当且仅当对所有 `x`，`χᴮ(x) ≤ χᶜ(x)`。

Bag 的基数是所有重数之和：

> `|B| = Σₓ χᴮ(x)`。

因此 `{a,b,b}ᵦ` 的基数是 3，而不同元素的数量只有 2。Bag singleton 的基数为 1，即使它的元素本身是复杂 tuple 或嵌套值。

## NULL 是一个按点等号归并的元素

Bag 的重数必须先确定元素相等。原书沿用第五章的点等号：

```text
{NULL, NULL, NULL}ᵦ
```

表示 NULL 这个元素的重数为 3。它不是三个各自重数为 1 的不同元素。这个选择与 SQL 的重复消除、分组和 DISTINCT 语义一致。

需要区分两件事：NULL 作为一个值可以参与重数归并；比较谓词 `x = y` 仍可能返回 UNKNOWN。Bag 的元素相等规则和 SQL WHERE 的真值规则处在不同层次。

## Bag 不是“集合加上一列 count”这么简单

计数列是 Bag 的一种表示方式，但 Bag 语义首先是函数 `χᴮ`。同一个 Bag 可以显式写出重复元素，也可以写成 `(element, multiplicity)` 的压缩形式。后续表示章节会讨论转换；本节先把重数当作语义定义，而不是某种执行存储格式。
