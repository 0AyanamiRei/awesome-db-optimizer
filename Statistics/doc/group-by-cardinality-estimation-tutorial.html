Statistics & Cardinality Estimation Tutorial

GROUP BY 结果基数估计：从 Statistics 到 Every Row Counts

先记住一句话

Every Row Counts 的标题指向职责分工： 单列 sketch 在维护期看过每一行，因此单列 NDV 很准； row sample 保留多列组合，因此能观察相关性。 论文用单列全量信息去约束多列 sample-only estimator，而不是把几个 HLL 值直接相乘。

1. Estimate 在优化器中的位置

Book §5.1 把 cost estimation 放在 plan search 的内循环里：搜索器产生或访问候选计划， cost model 估算每个物理算子的资源消耗，而 cardinality estimation 为这些公式提供输入、输出行数。 统计摘要则是 cardinality estimator 观察真实数据分布的窗口。 Book §5.1 · PDF 135–136

1.1 Cost、cardinality、statistics 不是同义词

Statistics

关于数据分布的有限摘要，例如 row count、NDV、null count、MCV、histogram 或 sample。

Cardinality estimate

把统计摘要与算子语义结合，预测一个逻辑表达式会输出多少行。

Cost estimate

把输入/输出 cardinality、row width、硬件参数和物理算法放进资源公式，得到可比较的分数。

1.2 为什么 group 数量值得单独估

对 GROUP BY A, B，输出行数就是不同 \((A,B)\) 组合的数量。 这个数字既是聚合节点的 output cardinality，也影响 hash table 大小、是否可能 spill、 partial/final aggregate 的收益、shuffle 分布和上层 join 的输入。

教学用简化关系，不是指定论文中的 cost 公式 \[ \operatorname{Cost}(\text{HashAggregate}) \approx c_{\text{consume}}\cdot N + c_{\text{state}}\cdot D + c_{\text{emit}}\cdot D \]

其中 \(N\) 是输入行数，\(D\) 是 group 数。即使扫描同样的 \(N\) 行， \(D=10^2\) 与 \(D=10^8\) 也可能对应完全不同的内存压力和后续计划。

2. Book §5.2–5.3：Cost Model 与 Statistics 工具箱

2.1 Cost model 先问“处理多少”，再问“每单位多贵”

Book §5.2 将物理算子成本拆成三类因素：处理的数据量、每单位数据的 CPU/I/O 成本， 以及并行度、可用内存、buffer pool 等运行时因素。公式和参数通常是算子专属的； 参数还需要通过 micro-benchmark 或执行测量校准到具体硬件。 书中也提醒，缓存与并发等系统级状态难以在优化时准确预测，因此模型必然是选择性抽象。 Book §5.2 · PDF 136–139

教学边界

更复杂的 cost formula 不能补救完全错误的 group count。 反过来，准确的 \(D\) 也不能自动给出运行时间；它只是 cost model 的关键输入。

2.2 三类 synopsis 的能力不是一条“精度排行榜”

Book §5.3 给统计摘要列出五个评价轴：accuracy、efficiency、memory、coverage， 以及 creation/maintenance cost。不同摘要是在这些轴上交换能力。 Book §5.3 · PDF 139–148

2.3 Statistics 还有一个生命周期问题

Book §5.3.4 指出，系统不仅要“计算一个统计值”，还要决定创建哪些单列、多列或 view statistics， 以及数据更新到什么程度时重建。候选统计项本身是组合爆炸的；实际系统通常优先收集查询中出现的列， 用 workload relevance、潜在 plan impact 和维护成本做取舍。多数商业系统在显著比例的数据被更新后重建， 而不是对每次写入精确维护所有 histogram。 Book §5.3.4 · PDF 148–151

这正是 Every Row Counts 的设计约束

为 \(C\) 列维护 \(C\) 个单列 sketch 是线性的；为所有非空列组合维护 \(2^C-1\) 个 sketch 是指数的。论文追求的不是“预先知道所有组合”，而是用线性数量的全量摘要 去修正一份能够临时投影到任意列组合的 sample。

3. GROUP BY NDV：单列都知道，组合仍可能完全不知道

SELECT A, B, SUM(C)
FROM R
GROUP BY A, B;

令 \(N=|R|\)，令 \(D=|\pi_{A,B}(R)|\)。优化器真正要估的是 \(D\)， 即不同 \((A,B)\) tuple 的数量，而不是输入行数 \(N\)。 对每个单列，假设已有 \(D_A\) 和 \(D_B\)，则只能得到很宽的必然边界：

\[ \max(D_A,D_B) \le D \le \min(N,D_A D_B) \]

完全相关

若每个 A 值总是只对应一个 B 值， \(D_A=D_B=100\) 时，组合 NDV 可以只有 \(100\)。

接近独立

若 100 个 A 与 100 个 B 的组合几乎都出现， 同样的单列 NDV 会对应 \(D\approx 10\,000\)。

所以“把单列 NDV 相乘”隐含了很强的独立性假设；“取最大单列 NDV”又隐含了近乎函数依赖。 一份行样本至少保留了 A 与 B 同行出现的关系，但新问题随之而来： 没被抽到的 rare groups 到底还有多少？ CIDR §1 · PDF 1–2

全表 样本 含义

4. Every Row Counts 的完整结构

论文把问题拆成三个可以独立理解的部件：单列全量摘要、样本上的 estimator， 以及计算 frequency vector 的快速路径。最终 estimator 不是某一个 HLL register 的读数， 而是把 sample-derived estimated bounds 与 per-column estimated corrections 组合起来。

系统前提：每列随写入维护一个 counting HLL；系统还需提供一份可以投影任意列组合的 row-uniform sample。论文使用该 sample，但没有给出它在 DML 下的动态维护算法。
优化期：对当前 GROUP BY 列从 sample 计算 \(f_1,\ldots,f_q\)，并计算各单列的 \(f_{i,j}\)，先得到 sample-only 的 BC estimated bounds。
修正期：counting HLL 只估计 \(D_j\)；Equation 12 再把 \(\hat D_j\) 与 单列 sample frequency classes 合成 \(\hat F_{1,j}\)，形成 estimated corrections 并得到 SCBC。

5. 第一个部件：Counting HLL 为什么“每行都算数”

5.1 传统 HLL 的直觉

对一个近似均匀的 64-bit hash，前导零至少有 \(i\) 位的概率约为 \(2^{-i}\)。 如果观察到很长的前导零串，通常意味着已经看过很多不同值。传统 HLL 用前 \(b\) 个 bit 把 hash 分到 \(m=2^b\) 个 bucket，在每个 bucket 记录剩余 bit 的最大前导零数， 再聚合多个 bucket 以降低单次极值的方差。 CIDR §2.1 · PDF 2

\[ \text{expected relative error} \approx \frac{1.04}{\sqrt{m}} \]

论文取 \(m=64\)，传统状态只需 64 bytes，并使用 Ertl 的改进 estimator 处理低 cardinality bias。

5.2 删除为什么迫使状态变大

传统 bucket 只记最大前导零数。若删除的值恰好支撑当前最大值，系统不知道是否还有另一个值也支撑它， 因而无法判断 bucket 是否应下降。Counting HLL 为每个 bucket 的每种可能前导零数保存一个 count； 删除后仍能找到最高的非零 count。

精确计重要的小 count

每个 1-byte counter 的前 128 次出现精确计数。最大前导零通常只由少数值支撑，这一段最重要。

概率计不重要的大 count

超过 128 后，一个 byte 表示指数增长区间；increment/decrement 保持期望正确，而不是精确 multiplicity。

“支持删除”不等于精确集合

论文的 probabilistic counter 对大 multiplicity 保持 expected-correct behavior。 它让 HLL 估计在频繁 deletion workload 下维持近似精度，不把 distinct set 变成精确 hash set。 CIDR §2.2 · PDF 3

6. 第二个部件：Sample、Frequency Vector 与 GEE

论文理论部分为与前作可比，主要讨论从 \(N\) 行中进行有放回的均匀 row sampling； 对无放回 sampling 另给近似下界。无论哪种，估计器的直接输入都不是 raw rows， 而是 sample 上的 frequency vector：

\[ f_i = \#\{\text{sample 中恰好出现 }i\text{ 次的不同 grouping tuples}\} \] \[ n=\sum_{i=1}^{q}i f_i,\qquad d=\sum_{i=1}^{q}f_i \]

6.2 Ratio error 与“不可能免费知道 unseen groups”

\[ \operatorname{ratioError}(\hat D) = \max\left(\frac{D}{\hat D},\frac{\hat D}{D}\right) \]

Charikar 等人的负面结果表明，只检查 \(n\) 行的 estimator， 在某些输入上无法避开量级为 \(\sqrt{N/n}\) 的 ratio error。 GEE（Guaranteed Error Estimator）在这个最坏界意义下是基线： 它假设 sample 中重复出现的 groups 已大致被看见，把不确定性集中到 singleton。 CIDR §3.1 · PDF 4

GEE：singleton bounds 的几何平均 + 已观察到的 non-singleton groups \[ \hat D_{\mathrm{GEE}} = \sqrt{\frac{N}{n}}\,f_1+\sum_{i=2}^{q}f_i \]

GEE 把全表 singleton 数放在 \([f_1,\,Nf_1/n]\) 内，并取两端的几何平均。 当 sample fraction 是 1% 时，两端相差 100 倍，几何平均仍可能与真值相差 10 倍； 这就是“最坏界最优”与“工程上足够准”之间的距离。AE 会根据 sample 分布自适应修正， 但论文实验显示它在部分 skew 分布上仍不稳定。

7. 第三个部件：从 BC 到 Sketch-Corrected BC

7.1 BC 先从 sample 自己推 estimated bounds

Bound-Corrected estimator（BC）不满足于 GEE 的固定 singleton 下界。 论文从 sample singleton 的期望 \(\mathbb{E}[f_1]\) 和 sample distinct count 的期望 \(\mathbb{E}[d]\) 推导全表 \(D\) 的不等式，再把一次 sample 观察到的 \(f_1,d\) 代入，得到以下 estimated lower/upper bounds： CIDR §3.2 · PDF 4–5

Equations (5)–(6)：由 expectation inequalities 得到的 plug-in estimates \[ \hat L= \begin{cases} \displaystyle\frac{1}{1-(f_1/n)^{1/(n-1)}}, & f_1\ge n(1-1/n)^{n-1},\\[8pt] \displaystyle\frac{f_1}{(1-1/n)^{n-1}}, & \text{otherwise}, \end{cases} \] \[ \hat U=\frac{d}{1-(1-1/N)^n} \]

Estimated bound 不是 confidence interval

Theorem 1/2 约束的是 \(\mathbb{E}[f_1]\) 与 \(\mathbb{E}[d]\)。把一次 sample 的 \(f_1,d\) 代入后，\(\hat L,\hat U\) 只是 plug-in estimates，不保证每次都夹住真实 \(D\)。 论文还执行 hard sanity clamp：\(d\le\hat L,\hat U\le N\)。

把 D estimated bounds 转成 singleton estimated bounds \[ \hat L_{\mathrm{BC}} = \max\left(f_1,\hat L-\sum_{i=2}^{q}f_i\right) \] \[ \hat U_{\mathrm{BC}} = \min\left(\frac{Nf_1}{n},\hat U-\sum_{i=2}^{q}f_i\right) \] \[ \hat D_{\mathrm{BC}} = \sqrt{\hat L_{\mathrm{BC}}\hat U_{\mathrm{BC}}} +\sum_{i=2}^{q}f_i \]

7.2 单列 sketch 怎样约束多列 group

令 \(\hat D_j\) 是第 \(j\) 列 counting HLL 给出的全表 NDV。 论文继续沿用“sample 中 non-singletons 大致已被看见”的假设， 把该 HLL estimate 与单列 sample frequency classes 组合，估计全表单列 singleton 数：

\[ \hat F_{1,j}=\hat D_j-\sum_{i=2}^{q_j}f_{i,j} \]

因此 \(\hat F_{1,j}\) 不是 HLL register 的直接读数，也不是真实 \(F_{1,j}\) 的保证下界； 它是由 HLL 与 sample 共同得到的 estimated correction。

对真实值而言，任一列上的 singleton value 一旦与其他列拼成 tuple，仍只能出现在那一行，因此 多列 singleton 数至少是各单列 singleton 数的最大值；多列组合数也不会超过各单列 NDV 的笛卡尔积：

\[ \max_j(F_{1,j})\le F_1\le\prod_jD_j, \qquad \max_j(D_j)\le D\le\prod_jD_j \]

上式对真实 \(D_j,F_{1,j}\) 是 exact structural bounds；把它们替换为 \(\hat D_j,\hat F_{1,j}\) 后，SCBC 使用的是 estimated corrections，而不是新的确定性保证。

\[ \hat L_{\mathrm{SCBC}} =\max\left(\hat L_{\mathrm{BC}},\max_j\hat F_{1,j}\right) \] \[ \hat U_{\mathrm{SCBC}} =\min\left(\hat U_{\mathrm{BC}},\prod_j\hat D_j\right) \] \[ \hat D_{\mathrm{SCBC}} =\sqrt{\hat L_{\mathrm{SCBC}}\hat U_{\mathrm{SCBC}}} +\sum_{i=2}^{q}f_i \]

论文还要求所有 sketch-corrected point estimates 使用 Inequality 11 做 final NDV sanity clamp。 同时加入必然的 \(D\le N\) 后，可写为：

\[ \hat D_{\mathrm{final}} =\operatorname{clamp}\!\left( \hat D_{\mathrm{SCBC}}, \max_j\hat D_j, \min\!\left(N,\prod_j\hat D_j\right) \right) \] \(\operatorname{clamp}(x,\ell,u)=\min(u,\max(\ell,x))\)；端点本身仍是 estimates

7.3 用原文 Figure 5 的数字走一次 correction

原文构造一个 \(N=100\,000\)、\(n=1\,000\) 的双列表。 全表有 \(D=75\,000\) 个不同 tuple，其中 \(F_1=50\,000\)； sample 中 \(d=1\,000\)、\(f_1=750\)。 两个单列的全表 NDV 分别为 \(50\,000\) 与 \(30\,000\)，单列 singleton 数为 \(25\,000\) 与 \(15\,000\)。 CIDR Figure 5 · PDF 6

sample 中已观察到的 non-singleton identities 为 \(\sum_{i=2}^{q}f_i=d-f_1=250\)。GEE 估 singleton 为 \(\sqrt{N/n}\,f_1=\sqrt{100}\cdot750=7\,500\)，所以 total estimate 是 \(7\,500+250=7\,750\)。
由 Equations (5)–(6) 得 \(\hat L\approx3\,473.08\)、raw \(\hat U\approx100\,500.33\)；将 \(\hat U\) clamp 到 \(N\) 后为 \(100\,000\)。 因而 \(\hat L_{\mathrm{BC}}\approx3\,223.08\)、 \(\hat U_{\mathrm{BC}}=75\,000\)。
BC 的 singleton estimate 为 \(\sqrt{3\,223.08\cdot75\,000}\approx15\,548\)，即原文所说的约 \(16\,000\)； 加回 250 个 observed non-singleton identities，raw total estimate 约为 \(15\,798\)。
Figure 5 为解释 correction 直接给出真实单列 singleton 数 \(25\,000\) 与 \(15\,000\)； 实际算法中对应的是由 Equation 12 得到的 \(\hat F_{1,j}\)，并非 HLL 单独输出。 沿原文示例把它们作为 estimated correction values，SCBC lower endpoint 变为 \(\max(3\,223.08,25\,000)=25\,000\)。
单列 NDV 乘积 \(50\,000\times30\,000=1.5\times10^9\) 不能收紧 \(75\,000\) 的 BC upper endpoint。因此 SCBC singleton estimate 为 \(\sqrt{25\,000\cdot75\,000}\approx43\,301\)，加回 250 后 raw total estimate 约为 \(43\,551\)。
最后应用 total-NDV sanity clamp：下端为 \(\max(D_1,D_2)=50\,000\)，上端为 \(\min(N,D_1D_2)=100\,000\)， 所以该例最终 point estimate 为 \(50\,000\)。真实 \(D=75\,000\)；该 clamp 仍不是置信保证。

为什么这个例子值得保留

它同时展示了 sketch 的能力和局限：由 HLL 与 sample 合成的 singleton estimated lower endpoint 很有用； 但 \(D_1D_2=1.5\times10^9\) 大于 \(N\)，乘积上界在高 NDV 场景几乎没有信息。 论文实验也观察到 sketch correction 对较小 cardinality 更有效，而 BC 的新 estimated bounds 主要改善较大的 cardinality。

8. 第四个部件：不用整行 Hash Table 也能算 Frequency Vector

所有 sample estimator 都需要 \(f_i\)。最直接的办法是把选定 grouping columns 拼成宽 tuple， 插入 hash table 后统计 multiplicity；但宽行 hash/compare、容量预估和随机访存的常数都不小。 论文 §4 改用 string partition refinement：把每行看成由多列字符组成的字符串， 按列逐层把 row-index partition 细分。 CIDR §4 · PDF 7

8.1 论文实现上的三个加速点

  • 先剪 singleton rows：某行在任一选定列上出现 singleton value，则它的完整组合必为 singleton。
  • dictionary encode + bit packing：sample 的列值编码到最多 \(\lceil\log_2n\rceil\) bits，把多个列值装进 machine word 一起 partition。
  • 高 NDV 列优先：越早把 partition 切小，越多分支能提前到达 \(|P|=1\) 的 base case。

原文最终选择在 partition 内原地 sort，再线性扫描边界；各 partition 不重叠， 整个递归可以复用一份 row-index auxiliary array。这里的贡献是优化常数和宽表访问形状， 不是改变 \(D\) 的统计推导。

论文在插入并周期性删除随机值的 workload 上，counting 与 traditional HLL 的 mean/99th ratio error 都为 1.13/1.34。对 1000 万行、10 列的表，traditional HLL 的 column-wise 构建为 132ms，counting HLL 为 340ms，比例约 2.58×；row-wise 则为 111ms 与 370ms， 比例约 3.33×。因此论文正文的概括性“约 2.5×”不能代表两种 layout。 论文还报告 TPC-H bulk load 同时维护所有列 sketch 的时间增加约 5%。这些数字来自 2019 年论文硬件， 只能说明 feasibility，不能当作现代系统 SLA。 CIDR §5.1 · PDF 8–9

原文内部数字冲突：以 Table 4/5 为准

PDF p.10 正文称 BC 的 mean ratio error 低于 2.0 时，只需 0.05% synthetic sample 与 0.01% real-world sample；但同页 Table 4/5 中 BC 在这两行分别是 3.3 和 5.9。 表格实际首次低于 2.0 的对应行是 0.5%（synthetic，1.8）与 0.1%（real-world，1.8）。 本文采用可逐格核对的表格数值，不复述正文中的十倍采样率偏差。

原文交叉引用错误：SCGEE 下界来自 Inequality 10

PDF p.6 的 SCGEE 段落说 singleton lower bound 使用 Inequality 11； 实际的 \(\max_j F_{1,j}\le F_1\) 是 Inequality 10，Inequality 11 约束的是 total NDV \(\max_j D_j\le D\le\prod_j D_j\)。本文按公式含义引用，不沿用该编号误植。

9.3 Frequency computation：不要只看夸张的最大 speedup

与预分配好的 hash-table baseline 相比，递归实现的 median speedup 是 9.3×， 但跨配置的 speedup 分布很宽；99th percentile 约 8,700× 主要反映不同数据形状和早停机会， 不代表固定加速比。更可迁移的证据是绝对延迟：论文配置中 proposed 方法 mean 0.38ms、 p99 2.81ms；在 32,768 行、1,024 列的极端 synthetic sample 上，单次 frequency vector 计算至多 3.4ms，给定 vector 后 estimator 通常少于 5µs。 CIDR §5.3 · PDF 11–12

10. Review：论文证明了什么，没有证明什么

材料支持的结论

  • 对单列，full-information HLL 比小 sample 的 NDV 外推更稳定。
  • 对任意列组合，一份 row sample 可以复用；论文实验表明，HLL 与 sample 共同形成的 estimated corrections 整体改善了 sample estimator。
  • BC 与 sketch correction 在算法上是两个可分别观察的改进，SCBC 在论文评测中整体最好。
  • frequency vector 不一定需要宽 tuple hash table，partition refinement 对宽 sample 有实际价值。

材料没有证明的结论

  • 没有证明 SCBC 在所有分布、所有 sample fraction 上都有小误差。
  • 没有直接覆盖 join result 或任意 filter 后的 GROUP BY；普通单列 sketch 也不支持任意 predicate conditioning。
  • 没有证明一个 2019 prototype 的维护成本适合所有并发、持久化与事务设计。
  • 没有把更准的 \(D\) 转化成 end-to-end plan/runtime 改善实验。

10.1 最容易忽略的四个实现边界

  1. Sample 至少要有最小行数。 论文 real-world 实验在 0.01% 时某些 sample 只有 4 行；作者也建议实践中设置 minimum sample size。
  2. Row-uniform 假设不是免费获得的。 如果底层实际抽的是 tablet/page/block，layout correlation 会改变 frequency classes。 这正是 SIGMOD 2004 专题 要解决的另一层问题。
  3. Sketch product bound 可能极松。 高 NDV 列相乘很快超过 \(N\)；此时主要依靠 BC，而不是 sketch upper bound。
  4. Correlation 不等于只看 Pearson \(\rho\)。 论文 synthetic 实验在其生成模型中观察到不同 correlation 下精度相近， 不能外推成任意真实相关结构都不影响 estimator。

与 SIGMOD 2004 的正确连接方式

Book §5.3.3 已经指出：均匀 row sample 往往需要触达大量页面，所以系统会抽 page/block； 但同页数据相关会让 sample 不再 row-uniform。 SIGMOD 2004 为 histogram 提出 2PHASE，为单列 NDV 提出 COLLAPSE。 它与 CIDR 2019 是相邻问题，不是同一个算法的前后两章。 Book §5.3.3 · PDF 147–148

11. 从论文回到开源系统：先区分四条路径

生产系统中至少有四件常被统称为 “sampling / estimates” 的事：

① Statistics collection

ANALYZE 如何选择 table/tablet/page/row，计算 NDV、null count、min/max、histogram。

② Statistics storage

落盘或缓存的是 numeric NDV、HLL state、MCV、histogram，还是扩展多列统计。

③ Optimizer estimation

逻辑 Aggregate 如何把一个或多个 grouping expression 的统计传播成 output row count。

④ Query-facing sampling

TABLESAMPLE / SAMPLE 是用户查询算子；它不自动等于 ANALYZE 的内部采样。

Doris 的关键对照点

当前 Doris Nereids 的 GROUP BY row-count 路径读取各 grouping expression 的单列 NDV， 按 NDV 降序后用固定 correlation coefficient 逐列衰减乘积，并把结果 clamp 到 child row count； 若统计未知则回退到 child rows 的固定比例。统计收集侧会在 OLAP tablet sample 上计算/外推单列 NDV。 这两段已经构成一条完整的工程链，但不是 CIDR 论文的 counting-HLL + row-sample + SCBC。 具体类、公式、版本快照和 PostgreSQL/DuckDB/ClickHouse 对照见 开源数据库 Statistics / Estimates / Sampling 调查。

Cost model 和 cardinality estimator 谁依赖谁？ Cardinality 为物理 cost 公式提供 rows/width；statistics 为 cardinality 提供分布摘要。 §1

最后的心智模型

Histogram、sketch、sample 都不是“真实数据的廉价副本”，而是有明确可见范围的观测器。 好的 estimator 不会假装某一种观测器知道一切；它会把每条信息能证明的上下界写清楚， 在组合时保留不确定性，并让 optimizer 知道这个点估计来自什么假设。
