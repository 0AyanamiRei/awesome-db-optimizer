# L06b · 量词、条件分配与第 5 章练习

原文：§5.1 图 5.2、§5.3 图 5.4–5.5 后的 Exercise 1–3，印刷页 200、203–204，[PDF 第 221、224–225 页](../../Query%20opt.pdf#page=221)。前六节已经建立了普通值、NULL、三值逻辑、解释操作和等价类；本节补上原书图 5.2 中没有在前文展开的量词规律，并把三个练习整理成可以核对的答案。量词的精确定义和机器指令模型在原书这里没有完整展开，相关地方会明确标出教学约定。

## 量词是在什么范围内检查条件

图 5.2 中的 `∃e p` 和 `∀e p` 可以先读成：

- `∃e p`：在 `e` 的取值范围内，至少有一个值使 `p` 成立；
- `∀e p`：在 `e` 的取值范围内，每个值都使 `p` 成立。

为了看清空范围的影响，设 `D` 是 `e` 可以取的值集合，先使用二值逻辑：

> `∃e p` 在 D 为空时为 FALSE；
>
> `∀e p` 在 D 为空时为 TRUE。

第二条不是说“空集合中的每个值都真的满足条件”，而是全称要求没有找到反例。它是后面条件分配式必须单独处理空范围的原因。

`p₁` 如果不引用 `e`，就可以把它看成量词范围外已经算出的一个固定条件。原书把这个要求写成自由属性不与 `e` 的绑定属性相交；这里先用一句话记住：**只有不依赖被量化变量的条件，才能从量词内外移动。**

## 图 5.2 中的量词规律

### 同类量词可以交换

同一类量词的嵌套顺序不影响结果：

> `∃e₁ ∃e₂ p ≡ ∃e₂ ∃e₁ p`
>
> `∀e₁ ∀e₂ p ≡ ∀e₂ ∀e₁ p`

例如，“存在一个客户和一个订单使连接条件成立”不依赖我们先枚举客户还是先枚举订单。这里交换的是两个绑定的检查顺序，不是说 `∃` 和 `∀` 可以互换；`∃e₁∀e₂ p` 与 `∀e₂∃e₁ p` 一般表达不同的问题。

### 量词可以分配到匹配的连接词

当同一个变量出现在两个分支中时，下面两条总是成立：

> `∃e (p₁ ∨ p₂) ≡ (∃e p₁) ∨ (∃e p₂)`
>
> `∀e (p₁ ∧ p₂) ≡ (∀e p₁) ∧ (∀e p₂)`

第一条的理由是：某个值使“左边或右边”成立，当且仅当某个值使左边成立，或某个值使右边成立。第二条则是：所有值同时满足两个条件，当且仅当所有值满足左条件且所有值满足右条件。

量词与连接词的另一种配对，需要把不依赖 `e` 的 `p₁` 移到量词内部：

> `p₁ ∨ (∀e p₂) ≡ ∀e (p₁ ∨ p₂)`
>
> `p₁ ∧ (∃e p₂) ≡ ∃e (p₁ ∧ p₂)`

这两条即使 `D` 为空也成立。第一条在空范围时两侧都为 TRUE；第二条在空范围时两侧都为 FALSE。

### 为什么另外两条要写空范围分支

下面两条在 `D` 非空时成立：

> `p₁ ∨ (∃e p₂) ≡ ∃e (p₁ ∨ p₂)`，当 `D ≠ ∅`；
>
> `p₁ ∧ (∀e p₂) ≡ ∀e (p₁ ∧ p₂)`，当 `D ≠ ∅`。

`D` 为空时，必须保留原书图 5.2 的分支：

> `p₁ ∨ (∃e p₂)` 的结果是 `p₁`；
>
> `p₁ ∧ (∀e p₂)` 的结果是 `p₁`。

例如令 `p₁=TRUE` 且 `D=∅`。左边的 `TRUE ∨ ∃e p₂` 为 TRUE，但右边的 `∃e(TRUE ∨ p₂)` 仍然为 FALSE；如果忽略空范围，就会把两个不同结果误写成等价。数据库优化器在移动量词或相关子查询条件时，必须知道绑定范围是否可能为空。

## 量词的否定

否定与量词交换时，存在和所有会互换：

> `¬(∀e p) ≡ ∃e (¬p)`
>
> `¬(∃e p) ≡ ∀e (¬p)`

这和“没有一个值满足 `p`”等于“所有值都不满足 `p`”是同一个意思。若 `D` 为空，`∀e p` 为 TRUE，左侧否定为 FALSE；右侧 `∃e ¬p` 也为 FALSE，所以空范围不会破坏这两条式子。

在三值逻辑中，原书指出图 5.2 中没有标星号的等价式仍可保留；标星号的排中律和矛盾律需要排除 UNKNOWN。量词如果要在三值域上使用，还必须明确“存在”和“所有”如何汇总 UNKNOWN。一个常见的教学约定是：存在在找到 TRUE 时为 TRUE、没有 TRUE 但有 UNKNOWN 时为 UNKNOWN，否则为 FALSE；全称在找到 FALSE 时为 FALSE、没有 FALSE 但有 UNKNOWN 时为 UNKNOWN，否则为 TRUE。这个汇总规则是本教材的补充说明，原书第 5 章没有单独完整定义它。

## Exercise 2：蕴含和异或的三值真值表

原书定义：

> `a ⇒ b := ¬a ∨ b`
>
> `a ⋅∨ b := (a ∨ b) ∧ ¬(a ∧ b)`

把上一节的 NOT、AND、OR 真值表直接代入，可得到：

| `a` | `b` | `a ⇒ b` | `a ⋅∨ b` |
| --- | --- | --- | --- |
| TRUE | TRUE | TRUE | FALSE |
| TRUE | FALSE | FALSE | TRUE |
| TRUE | UNKNOWN | UNKNOWN | UNKNOWN |
| FALSE | TRUE | TRUE | TRUE |
| FALSE | FALSE | TRUE | FALSE |
| FALSE | UNKNOWN | TRUE | UNKNOWN |
| UNKNOWN | TRUE | TRUE | UNKNOWN |
| UNKNOWN | FALSE | UNKNOWN | UNKNOWN |
| UNKNOWN | UNKNOWN | UNKNOWN | UNKNOWN |

例如 `UNKNOWN ⇒ FALSE` 为 UNKNOWN：先取否定得到 UNKNOWN，再与 FALSE 做 OR，结果仍为 UNKNOWN。`FALSE ⇒ UNKNOWN` 却为 TRUE，因为 `¬FALSE` 已经为 TRUE，OR 的一边足以确定结果。

Exercise 2 要检查的正是这件事：手工表格必须与定义右侧逐行一致；不能把“蕴含”重新当成二值逻辑里的独立黑箱，也不能因为出现 UNKNOWN 就把所有结果都写成 UNKNOWN。

## Exercise 3：把解释操作下推到蕴含和异或

蕴含只是 `¬a ∨ b` 的缩写，所以可以直接复用 L04 的规则。FALSE interpretation 的结果是：

> `⌊a ⇒ b⌋⊥`
> `≡ ⌊¬a ∨ b⌋⊥`
> `≡ ⌊¬a⌋⊥ ∨ ⌊b⌋⊥`
> `≡ ¬⌈a⌉⊥ ∨ ⌊b⌋⊥`

TRUE interpretation 则是：

> `⌈a ⇒ b⌉⊥ ≡ ¬⌊a⌋⊥ ∨ ⌈b⌉⊥`

异或的定义有一个 AND 和一个 OR，因此需要在遇到内部否定时交换解释方向：

> `⌊a ⋅∨ b⌋⊥`
> `≡ (⌊a⌋⊥ ∨ ⌊b⌋⊥) ∧ ¬(⌈a⌉⊥ ∧ ⌈b⌉⊥)`

对应地：

> `⌈a ⋅∨ b⌉⊥`
> `≡ (⌈a⌉⊥ ∨ ⌈b⌉⊥) ∧ ¬(⌊a⌋⊥ ∧ ⌊b⌋⊥)`

这两条式子说明了为什么 `pushunk` 不能只记住当前最外层是 TRUE interpretation 还是 FALSE interpretation。每经过一个 NOT，方向都会反转；复合定义中的 NOT 也一样。

## Exercise 1：两位编码的边界

原书要求为 TRUE、FALSE、UNKNOWN 找一个两位编码，使每个逻辑操作只需一条机器指令。这个练习缺少一个关键前提：没有指定机器指令集，不能声称存在一个对所有处理器都相同的答案。

在常见的逐位 AND/OR 模型中，一个有用的编码是：

| 真值 | 编码 |
| --- | --- |
| FALSE | `00` |
| UNKNOWN | `01` |
| TRUE | `11` |

此时三值 AND 和 OR 分别可以直接用逐位 AND、逐位 OR 实现：`00 < 01 < 11` 正好对应 FALSE、UNKNOWN、TRUE 的信息顺序。比如 `TRUE AND UNKNOWN` 是 `11 AND 01 = 01`，`FALSE OR UNKNOWN` 是 `00 OR 01 = 01`。

但普通逐位取反会把 `01` 变成 `10`，而 `10` 没有被定义为 UNKNOWN。因此，“AND 和 OR 能各用一条普通位指令”并不能自动推出 NOT 也能用一条普通位指令。要完成原题的强版本，还需要说明一种支持三值查表、条件选择或专用三值逻辑的机器指令；不同 ISA 的答案会不同。

这个练习的学习重点是把**逻辑代数**与**具体机器表示**分开。前面的等价式只依赖真值定义；两位编码还要额外证明编码、指令语义和未使用位模式之间的一致性。本教材不把某个未指定 ISA 的编码方案当作原书已经给出的结论。

## 第 5 章的最终检查表

到这里，第 5 章的知识接口可以完整地写成：

1. 二值逻辑先规定普通连接词和恒等式；
2. NULL 扩展值域，比较可能产生 UNKNOWN；
3. 三值逻辑规定 UNKNOWN 如何参与 NOT、AND、OR；
4. WHERE、CHECK 等上下文分别解释最终 UNKNOWN；
5. 先 `pushnot`，再 `pushunk`，把解释落实到叶子比较；
6. 只有在合取条件、解释方式和 NULL 行为都满足前提时，才建立相等类并替换属性；
7. 量词移动还要检查变量依赖和空绑定范围；
8. §5.6 只有标题，完整的 nullability inference 需要后续资料，不能从本章目录推造出来。
